title: Pack 格式
description: Lorelum Knowledge Pack 的完整文件格式，包括按需使用的资源。
---

Knowledge Pack 是一个带版本的目录：其中包含可独立召回的 Practice，以及可选的补充资源。第一次创建小型 Pack 请先看[创建 Pack](../create-pack)；需要完整格式和资源规则时，以本页为准。

## 目录结构

```text
<pack-root>/
├── pack.yaml
├── practices/
│   └── **/*.md
├── decisions.yaml                 # 可选
├── references/                    # 可选
├── assets/                        # 可选
├── scripts/                       # 可选
└── i18n/                          # 仅供编写期人工审阅的本地化 companion
```

`pack.yaml` 标识 Pack 及其版本。所有 canonical runtime Practice 放在 `practices/` 下，并带有必填的 Practice frontmatter。存在 `decisions.yaml` 时，它提供既有的 decision graph。`i18n/` 仍是面向人工审阅的 companion，不构成第二套 runtime Pack。

三个资源目录是 Pack 的普通内容，不是另一套附件系统：

| 目录 | 适合放什么 | 不应放什么 |
| --- | --- | --- |
| `references/` | 仅在部分场景需要的详细规则、证据、兼容矩阵、字段定义或长篇 runbook。 | 当前 Practice 作出立即判断时唯一需要的事实。 |
| `assets/` | 调用方会复制到任务产物中的模板、检查清单、配置骨架、starter 文件或其他材料。 | 已安装 Pack 内可直接编辑的工作目录。 |
| `scripts/` | 调用方可显式运行的、可重复的诊断、检查或转换程序。 | 安装 hook、隐式依赖安装、凭据读取或自动联网工作。 |

每个资源随所选 Pack artifact 一起保存。资源不是独立的可检索对象：其字节不进入 Practice 排名，也不进入 semantic/keyword index。

## 在 Practice 中链接资源

使用普通 Markdown link，并把 target 写成 `resource:`。`resource:` 后的路径相对 Pack root 解析，而不是相对 Practice 文件：

```markdown
当改动涉及公开 API 边界时，阅读 [API 兼容矩阵](resource:references/api-compatibility.md)。

将[评审报告模板](resource:assets/api-review-report.md) 复制到任务工作区后再填写。

需要重复诊断时，按下文的输入说明运行 [公开 API 检查脚本](resource:scripts/check-public-api/main.py)。
```

resource target 必须以 `references/`、`assets/` 或 `scripts/` 开头，并解析为同一个 Pack 内的普通文件。它不能离开 Pack root，也不能使用 symlink、fragment、query 或平台不安全的路径。普通网页链接、普通相对 Markdown link、inline code 和代码示例保持原有语义。

即时判断仍要写在 Practice 本身：触发条件、动作、直接原因、重要例外和停止点，必须在只召回这一条 Practice 时也能理解。link 的作用是说明什么时候需要更多细节或可复用产物，不能把唯一的安全条件藏在资源里。

## 发布前校验

```sh
lore validate /path/to/pack
```

校验会报告 Pack 的结构问题，包括资源目录安全以及缺失或非法的 `resource:` target。它不会执行 Pack script、安装依赖、联网、读取凭据、判断脚本业务逻辑，也不要求每个 helper 文件都被直接链接。一个脚本可以合法使用同目录 helper；一个 asset 目录也可以包含需要一起复制的文件组。

校验通过只说明格式正确。内容人工审阅、代表性查询下的召回表现，以及下游 Agent 行为仍应分别验证，再做相应声明。

## 调用方如何使用资源

执行 `lore get <practice-id>` 后，每个 source 会包含 `packName`、`sourcePath` 和当前本地 `packRoot`。该 root 是可直接读取的 `current` view，不是 artifact digest 目录。使用同一个 source 的 root 解析 `resource:` 路径。调用方明确选择一个 Pack 时，也可通过 `lore pack list <pack-name>` 或成功的 install/update 获得同类 locator。locator 的生命周期和多 source 规则见 [get 参考](./get)与[Pack 命令](./packs)。

这是一条路由约定，不是访问控制系统。`resource:` 推荐与当前 Practice 相匹配的材料；它不限制调用方浏览明确选择的 Pack root。不要从 Pack 名或 Store 内部实现推导路径。后续 mutation 可能让现有 `current` 路径解析到新 bytes，或使其消失；在把它作为当前 source 使用前重新执行 `lore get` 或 `lore pack list`。

reference 按需读取；asset 先复制到目标工作区再编辑；script 仅在当前任务授权、且 Practice 已明确输入和预期输出时显式运行。Lorelum 不会在 install、validate、query、list、get、index 或 recovery 期间自动运行 Pack script。

## 安装与检索的边界

安装或更新 Pack 会保存所选 Pack artifact，包括有效资源；不会注册 Host Skill、授予新权限或运行 script。仅修改资源会创建新的 Pack artifact，但不会改变用于检索的 canonical Practice 内容。修改 Practice 中的 `resource:` link 会改变该 Practice 的 canonical content，并遵循正常的 retrieval revision 生命周期。

格式以外的 Pack 编写指导，请安装并查询 [`pack-creator`](../create-pack#获取编写指导) Pack。
