---
title: Backend 命令
description: 启动、查看和停止 Lorelum 本地服务。
---

Backend 是承载 embedding 和 semantic index 操作的长期本地服务。start、status、stop 与 Store 选择相互独立。

```sh
lore backend start
lore backend status
lore backend stop
# 仅供 Agent 自动恢复使用
lore backend stop --if-idle
```

`start` 会初始化缺失的默认配置，启动或复用兼容的本地实例，并等待其 ready；不会加载模型。`status` 返回 `state`、`model`，以及可用时的 `instanceId`、`buildIdentity`，不会启动进程。显式 `stop` 等待服务退出，服务已停止时重复调用也安全。

升级后，当前 CLI 可以显式停止另一 build 的、已经验证为同一实例的本地 Backend。protocol 兼容时走 authenticated shutdown；protocol 不兼容时，当前 CLI 使用私有 runtime record 与精确进程身份，在 graceful deadline 后只终止同一 owned lifecycle。它不要求旧 CLI 仍存在，也不会因为某个进程占用了本地端口就终止它。

`stop --if-idle` 是支持的 Agent 自动恢复专用的受限动作。它在 lifecycle lock 内重新检查私有 activity 与 task lease：只有证明 idle 的 Backend 才会停止。模型准备、semantic indexing、有效 Agent lease 或无法判断 activity 时返回 `deferred`，另一任务保持不动。Agent 只有收到 query 的 `error.recovery` 时才会自动使用它，绝不会自主调用普通 `stop`。

默认服务地址为 loopback（`127.0.0.1:26186`）。全局 `--store-root` 只影响 Store 数据；`--log-level` 控制 stderr 的进度与诊断日志。

常见错误包括 `backend.unavailable`、`backend.port-conflict`、`backend.build-mismatch`、`backend.protocol-mismatch`、`backend.incompatible`、`backend.config-invalid`、`backend.busy`、`backend.failed` 和 `backend.deadline-exceeded`。build/protocol mismatch 的 query failure 会提供 machine-readable recovery，不要求用户处理 worktree 细节。成功退出 `0`，失败退出 `2`。各子命令 schema 见 `lore describe backend.start` 等。
