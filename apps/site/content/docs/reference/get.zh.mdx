---
title: get
description: 按精确 ID 读取一个当前生效的 Practice。
---

从当前 query context 读取完整 Practice。本命令只访问本地数据，不需要 Backend、模型或网络。发现 ProjectContext 时返回当前局部 winner；`--no-project` 强制只使用选中的 Store。

```sh
lore get <practice-id> [--store-root <path>] [--project-root <path>] [--no-project]
```

使用 [`query`](./query) 或 `lore pack list <pack>` 返回的精确 `id`；不接受标题、前缀或文件名。

```sh
lore get example.practice-id
```

成功 data 包含 `practice`（全文及元数据）、`contentDigest` 和 `sources`（`packName`、`sourcePath`、`packRoot`）。对于 Store source，`sourcePath` 相对其可读取的 `packRoot` current view，因此无需重复提供 `practicePath`，并可用该 root 解析 Practice 中的 `resource:references/api-compatibility.md` 这类 link。对于 ProjectContext source，`packRoot` 是 `project-layer-0` 这类安全逻辑 provenance，不是绝对文件路径，也不能作为 resource locator。

同一 Practice 有多个 source 时，应保持各自的 root，不能静默选中一个或合并多个 Pack 的资源。后续 Pack mutation 可能让相同的 current 路径解析到新 bytes，或随着 Pack 被移除而消失；应重新调用 `get`，或用 `lore pack list <pack-name>` 明确选择 Pack 后再使用，不能依赖 Store 内部实现推导新路径。reference 的读取、asset 的复制和 script 的显式运行规则见 [Pack 格式](./pack-format)。

将 query 返回的 `practiceId` 原样作为精确 `practice-id`。无效 ID 返回 `usage.invalid`；当前 query context 中不存在时返回 `practice.not-found`。Store 忙或需要恢复时分别返回 `store.busy`、`store.recovery-required`。

成功退出 `0`，声明的失败退出 `2`。精确结果 schema 见 `lore describe get`。
