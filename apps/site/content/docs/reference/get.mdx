---
title: get
description: Read one current Practice by its exact ID.
---

Read a complete Practice from the current query context. The command is local and does not need the Backend, model, or network. A discovered ProjectContext returns its current local winner; `--no-project` uses only the selected Store.

```sh
lore get <practice-id> [--store-root <path>] [--project-root <path>] [--no-project]
```

Use the exact `id` returned by [`query`](./query) or `lore pack list <pack>`; titles, prefixes, and filenames are not accepted.

```sh
lore get example.practice-id
```

Success data contains `practice` (the full Practice and metadata), `contentDigest`, and `sources` (`packName`, `sourcePath`, and `packRoot`). For a Store source, `sourcePath` is relative to its readable `packRoot` current view, so a separate `practicePath` is unnecessary; that root can resolve a Practice link such as `resource:references/api-compatibility.md`. For a ProjectContext source, `packRoot` is safe logical provenance such as `project-layer-0`, not an absolute filesystem path or resource locator.

If one Practice has multiple sources, retain each root separately: do not silently choose one source or combine resources from several Packs. A later Pack mutation can make the same current path resolve to newer bytes, or remove it with the Pack; call `get` again, or explicitly select a Pack with `lore pack list <pack-name>`, before treating it as the current source. Never derive a path from Store internals. See [Pack format](./pack-format) for how to read references, copy assets, and explicitly run scripts.

Use the `practiceId` returned by query as the exact `practice-id`. An invalid ID returns `usage.invalid`; an ID absent from the selected query context returns `practice.not-found`. Store contention and recovery report `store.busy` or `store.recovery-required`.

Exit `0` means success; all declared failures exit `2`. Run `lore describe get` for the exact result schema.
